# Security, privacy and legal review — 7 September 2026

This is a repository review and implementation record, not a penetration-test certificate or legal clearance. The changes are local and have not been deployed. No production database migration, live email test, live payment, or external account change was performed.

## Implemented

| Area | Finding and change |
| --- | --- |
| Authentication and public forms | Replaced per-process memory limits with atomic PostgreSQL counters. Login limits now cover both IP and account; registration, reset, newsletter and help requests cannot evade an IP bucket by rotating email addresses. Deleted users cannot log in; verification cannot reactivate disabled accounts. |
| Login redirects | Shared same-origin path validation rejects protocol-relative, backslash and control-character redirect bypasses. |
| Document downloads | An RFQ ownership check previously compared nullable company IDs. It now requires a real company association. Staff access is scoped to the document category, rather than allowing catalogue-edit permission to access arbitrary private documents. Signed redirects are private/no-store. |
| SQL injection | Reviewed Prisma query usage; no unsafe raw-query API found in source. New limiter queries use bound parameters. Object ownership and authorization still matter even with parameterized SQL. |
| CSV exports | Spreadsheet formula prefixes are neutralized in reporting exports, including whitespace-prefixed customer or product text. |
| Supplier content | Replaced a blacklist regex with reconstruction of allowlisted formatting tags, without any attributes. Other markup is escaped. This deliberately removes supplier links, images and inline styling. |
| Browser APIs | AI recommendations, AI cart, enquiries and browsing events enforce same-origin JSON requests. JSON is read with an actual byte cap, independent of Content-Length. Catalogue image uploads check browser origin and streamed aggregate size, including when Content-Length is missing. Declared formats are checked against decoded raster metadata; still images up to 24 megapixels are re-encoded as WebP, stripping EXIF/location metadata and appended payloads. Disguised HTML/SVG and format mismatches are rejected before storage. |
| AI abuse and cost | Atomic identity, IP and application-wide daily reservations happen before model calls. Failures consume allowance. Anonymous cookies are UUID-validated. The generic secret-protected AI endpoint is also rate limited and body bounded. Limits are request-count caps, not an exact currency budget. |
| AI authority | Existing structured intent, database candidate IDs, live prices/stock and cart ownership checks remain authoritative. Prompt instructions reinforce that user and catalogue text are untrusted. The shopping model has no account, email, SQL or payment tools. This does not guarantee all generated prose is correct or harmless. |
| Product requests | Guests provide name/email; account identity is obtained server-side. Explicit consent covers the previewed conversation and contact details. Staff receive escaped email content, a reference and an unverified-content label. Recipient is server-configured; customers cannot select arbitrary recipients. Database reservation prevents concurrent duplicate sends. Failed delivery does not show success. Existing failed-email retry tooling can handle provider failures. |
| Cookies and analytics | Optional event collection and browsing-history personalisation require the consent cookie, including at the API boundary. The choice expires after 180 days. Cookie settings lets customers withdraw consent. GA is disabled on withdrawal, accessible GA cookies are cleared, and recommendation-cookie deletion is requested. Analytics page locations exclude query/hash data. |
| Branding/accessibility | Existing Innozanzi mark is used in a cyan-ring AI badge in the launcher and panel. Keyboard focus cycles inside the modal. No new raster artwork or unrelated branding assets were modified. |
| Policies | Versioned terms, privacy, cookies and AI policies; clear human-enquiry processing notice; statutory returns supplement. The four source-controlled policy slugs now take precedence over old CMS copies. Other CMS policy slugs remain available. |
| Headers | Existing transport, frame, MIME and permissions headers retained; CSP now restricts base URLs, objects and framing. This is not yet a strict nonce-based script CSP. |

## Deployment requirements

1. Apply migration `20260907120000_security_rate_limits` before routing traffic to this code. Existing `npm start` already runs `prisma migrate deploy`. Missing database/table deliberately prevents protected operations, rather than falling back to unlimited use. Back up and rehearse the migration in an isolated environment first.
2. Set `NEXT_PUBLIC_SITE_URL` to the exact browser origin. Local development must use the local origin. Do not add wildcard origins.
3. Verify the ingress proxy overwrites a client-IP header, then set `TRUSTED_CLIENT_IP_HEADER` to that header. Never simply trust user-supplied X-Forwarded-For. Until configured, a conservative shared `unknown` bucket applies, potentially limiting unrelated customers together. Prevent direct access around the trusted proxy.
4. Confirm `PRODUCT_REQUEST_EMAIL` (default `support@innozanzi.co.za`), the live mail transport, mailbox access and failed-outbox monitoring. Guest contact details remain unverified. Provider acceptance is not proof of delivery into a recipient inbox. Sandbox mode is not live delivery.
5. Review defaults: AI anonymous 1/day, account 5/day, IP 20/day, global 200/day. Configure independent provider budget alerts/limits and edge request/connection/body limits. Distributed attackers can still exhaust a shared allowance; consider a bot challenge at the edge.
6. Use supported Node 22–24. The available local runtime was Node 25.2.1; npm warned about the mismatch, although checks passed. Repeat staging validation on the deployed supported runtime.
7. Schedule expiry cleanup of ordinary rate-limit rows. Keys beginning `product-request:` are delivery reservations and must not be deleted blindly: reconcile them against outbox records first. Do not retry an uncertain send by deleting its reservation. Counter rows contain hashes of identifiers; support/outbox records contain personal information.
8. Test account and guest requests in an isolated deployment with a controlled mailbox; test a missing product and an out-of-stock enquiry, a rejected model call, an email failure, a duplicate send, CSRF rejection and consent withdrawal. No live end-to-end email or browser visual test was performed here.

## Dependencies

The original production audit reported 11 affected packages (8 high, 3 moderate; no critical). Compatible patches were applied for PostCSS, fast-uri, nanoid, find-my-way, valibot and mysql2, plus development-tool brace-expansion and js-yaml updates.

The remaining three high entries were all in the Prisma → @prisma/config → deepmerge-ts chain, from one underlying recursive-merge denial-of-service advisory. A scoped `@prisma/config` override now uses patched deepmerge-ts 8.0.0. Prisma itself remains 7.9.0. Its configuration loader uses the same exported `deepmerge` function; generation, schema validation and production build are checked with this override. This is a major transitive override and should be removed when upstream Prisma adopts a compatible patched dependency. Recheck it on Prisma upgrades and rehearse migrations on the supported runtime.

The final npm install audit reports **0 known vulnerabilities across 560 audited packages**. This is a point-in-time registry result, not proof of absence of application vulnerabilities. No forced Prisma downgrade was applied.

## Follow-up verification

The catalogue image endpoint now parses multipart data only after enforcing a streamed byte limit, verifies the decoded format, rejects multi-frame images, and saves a metadata-free WebP. Tests cover disguised HTML/SVG, mismatched MIME, excessive pixel dimensions, metadata/appended-payload removal and size-header-free multipart overflow. The enquiry form also clears stale account-loading state on reopening and supports a new enquiry after successful submission with a fresh duplicate-submission key.

Implementation references: [Sharp constructor safeguards](https://sharp.pixelplumbing.com/api-constructor/) and [output metadata behaviour](https://sharp.pixelplumbing.com/api-output/). Image decoding is not a substitute for scanning general documents or verifying production storage permissions.
